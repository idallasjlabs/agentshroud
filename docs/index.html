OpenClaw

OpenClaw is AgentShroud's flagship production bot — a Node.js autonomous agent shipped as agentshroud-openclaw. It has been in production since v1.0.x and is the primary interface for Telegram, Slack, iOS Shortcuts, Browser Extension, SSH, and REST API — all traffic governed by the full 76-module security pipeline.

💬

Multi-Channel Presence

Telegram bot, Slack workspace integration, iOS Shortcuts, Browser Extension, SSH terminal access, and REST API — every channel routes through AgentShroud before reaching any downstream system.

🔒

Security Posture

All egress routes via gateway:8181 (HTTP CONNECT proxy). All LLM calls route via gateway:8080. PII is redacted at 0.9 confidence before any response reaches a user. Credentials are never leaked in chat — blocked at the sanitizer layer.

🧠

Persistent Memory

Per-collaborator workspace isolation with encrypted memory volumes. Conversation context, task history, and collaborator profiles persist across restarts on the agentshroud-config volume.

🖥️

Web Control UI

Built-in web dashboard at port 18789 (published at 127.0.0.1:18789). Manage devices, view conversation history, and configure channels without CLI access.

Hermes Agent

Hermes is the second AgentShroud-secured autonomous AI agent — Python-based, built on nousresearch/hermes-agent. It runs alongside OpenClaw inside the same 76-module governance envelope, fully isolated on the agentshroud-isolated network with all LLM and egress traffic routed through the gateway.

🤖

Capabilities

Telegram, Slack, Brave web search, web fetch, cron scheduling, subagent personas, and native MCP (Model Context Protocol) server integrations — all policy-enforced at the gateway.

🔒

Security Posture

🌐

OpenAI-Compatible API

Voice Terminal

The ESP32-S3-BOX-3 is an optional hardware control surface that lets you interact with any AgentShroud-proxied agent by voice — say "Hi, ESP" or tap the screen, speak naturally, and hear the agent's reply through the built-in speaker. All audio routes through the full 76-module security pipeline: PII redaction, prompt-guard, audit hash-chain, egress policy.

🎤

Wake Word + Tap-to-Talk

Say "Hi, ESP" or tap anywhere on the touchscreen. Short tap → VAD timeout (8 s silence ends utterance). Long press → ends on release.

🔄

Runtime Agent Toggle

Press the MUTE button to cycle between Hermes (agentic, synchronous reply), Fast LLM (low-latency Claude Haiku proxy), and OpenClaw (async — replies on Telegram).

🔒

Full Security Pipeline

Utterances route through POST /forward?route_to=<agent> — the same AgentShroud pipeline used by all other control surfaces. Token-authenticated WebSocket over Tailscale Funnel (TLS 443).

📡

Works Anywhere

Tailscale Funnel provides a public TLS endpoint on marvin. The device works on home WiFi, cellular hotspot, or any internet connection — no VPN client on the ESP required.

# Start the voice gateway
docker-compose -f docker/docker-compose.yml -p agentshroud --profile voice up -d

# Flash the firmware (ESP32-S3-BOX-3 on USB)
cd firmware/voice-terminal
idf.py -p /dev/cu.usbmodem* flash

Infrastructure

AgentShroud Infrastructure

Ships like a product, not a science project. Every release goes through a guarded blue/green deploy with automatic rollback, is validated across every runtime before it lands, and passes only on a genuinely healthy runtime. And because a security product must not hide its own vulnerabilities behind a green check, we publish our container-image CVE posture in full: as of v1.3.0, every container CVE with an available in-place fix is mitigated, verified against a fresh Trivy database (2026-07-15). Nothing is suppressed — the findings that remain have no upstream fix yet, and we enumerate each one with reachability analysis.

🟦

Blue/green canary deploy

A new ref is deployed to a GREEN canary and validated by post-deploy-check.sh before the BLUE production instance is ever touched. A failed health check auto-rolls-back to the previous ref; a pre-deploy-<UTC> tag anchors every rollback. No eval, refuses to run as the prod user.

✓ Live-validated on marvin

🖧

Multi-host validated deploys

One command runs the suite across every host over SSH and aggregates per-host PASS / FAIL / UNREACHABLE — a change is validated on every runtime (x86 + arm) before a coordinated rollout. A flaky host never aborts the sweep.

✓ Shipped

🩺

Honest health gates

Deploys pass only when the gateway serves /status 200 and the Docker network is clean. Startup warnings are curated and documented as known-benign — a green deploy means a genuinely healthy runtime, not a suppressed one.
