# OpenClaw Cron Jobs — Reference & Recreation Guide

Auto-generated snapshot of every OpenClaw cron job running in production, for
recreating the full job set on a fresh AgentShroud install. These jobs live
only in OpenClaw's live cron store (SQLite, `/home/node/.openclaw/state/
openclaw.sqlite` inside the container, on the `agentshroud-config` named
volume) — `docker/config/openclaw/cron/jobs.json` / `docker/bots/openclaw/
config/cron/jobs.json` are the *original* seed set and have drifted
significantly out of date (see "Known drift" below). A fresh volume starts
with whatever those two files seed — not what's captured here.

## How to recreate a job

Agent-turn jobs have their full prompt saved as a companion `.txt` file in
`docker/config/openclaw/cron/prompts/`. Command jobs' scripts live in
`docker/config/openclaw/cron/scripts/`. Two jobs also depend on template
files in `docker/config/openclaw/cron/templates/` (see "Shared dependencies"
below) — those must exist in the container's workspace *before* the
dependent jobs will succeed.

```bash
# Agent-turn job (reads its message from a file, avoids docker cp on the
# read-only rootfs — same incident class documented in the Hermes
# JOBS-REFERENCE.md: docker cp silently fails here, always pipe via stdin)
docker exec -i agentshroud-openclaw sh -c 'cat > /tmp/p.txt' < docker/config/openclaw/cron/prompts/<slug>.txt
docker exec agentshroud-openclaw sh -c 'openclaw cron add --name "<name>" --cron "<expr>" --tz "America/New_York" --agent main --session isolated --message "$(cat /tmp/p.txt)" --announce --channel telegram --to <chat-id> --timeout-seconds <n>'

# Command job (deterministic shell/python, no LLM)
docker exec agentshroud-openclaw sh -c 'openclaw cron add --name "<name>" --cron "<expr>" --tz "America/New_York" --session isolated --command "$(cat docker/config/openclaw/cron/scripts/<script>)"'
```

Deploy the 3 static files with the same stdin-pipe pattern (never `docker cp`):

```bash
docker exec -i agentshroud-openclaw sh -c 'mkdir -p /home/node/.openclaw/workspace/templates && cat > /home/node/.openclaw/workspace/templates/report-template.html' < docker/config/openclaw/cron/templates/report-template.html
docker exec -i agentshroud-openclaw sh -c 'cat > /home/node/.openclaw/workspace/templates/html-report-instructions.md' < docker/config/openclaw/cron/templates/html-report-instructions.md
docker exec -i agentshroud-openclaw sh -c 'cat > /home/node/.openclaw/workspace/.cve_prefetch.py' < docker/config/openclaw/cron/scripts/cve_prefetch.py
```

## Known drift from `docker/config/openclaw/cron/jobs.json`

The repo's static seed file still has the CVE Triage job as a single
LLM-driven job that fetches GitHub directly and self-manages its own cache
file. The live job has been split into the 3-job pipeline above (2
deterministic command jobs + 1 read-only report job) — this repo file has
not been updated to match. **Do not treat `jobs.json` as authoritative for
the CVE Triage job(s)** until it's reconciled; this file (JOBS-REFERENCE.md)
reflects live production as of 2026-08-24.

## 2026-08-24 incident history (for context, not action items)

- **CVE Triage file-write failure (investigated, resolved by the pipeline
  split above, not by this investigation):** the single-job design used to
  self-write a local cache file (`Write: to /workspace/.new-cves.json (95
  chars) failed`) as part of its own LLM-driven turn; when that write
  transiently failed, the whole run aborted with zero Telegram delivery.
  Someone had already redesigned this into the 3-job pipeline before this
  investigation — the reporting job no longer writes anything, eliminating
  the failure mode. 2 verified successful pipeline runs same night.
- **Collaborator Report jobs (Morning/Evening) — two real bugs found and
  fixed, both root-caused, not worked around.** (1)
  `CronSessionLifecycleClaimError: Session ... changed while starting work.
  Retry.` — OpenClaw's isolated cron sessions keep a claim lease in
  `agents/<id>/sessions/sessions.json`; when a run's setup fails/times out
  before producing a transcript file, the entry is left behind forever with
  no vendor-side reaper. A live audit found 15 of 19 stored session entries
  system-wide were stale this way, not unique to this job. Fixed via
  `openclaw sessions cleanup --fix-missing`, now run automatically every 30
  min (`docker/scripts/start-agentshroud.sh`, `session-cleanup` block). (2)
  Once the claim error stopped recurring, a real run still hit its
  `timeoutSeconds: 900` budget at 868s and got aborted — the sibling
  "Collaborator Daily Digest" job does near-identical work (same templates,
  same contributor-log read) at `timeoutSeconds: 1800` and succeeds
  reliably. Bumped both Collaborator Report jobs to 1800s to match.
- **11 abandoned `openclaw-sbx-*` sandbox containers found and removed** —
  root cause fixed durably in `docker/scripts/start-agentshroud.sh` (a
  30-min reaper loop); see that file's `sandbox-reaper` block.
