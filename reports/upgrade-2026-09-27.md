## §3 Bugs found and fixed this run (code changes, per owner directive — a needed fix is not grounds to skip)

1. **`docker/bots/openclaw/Dockerfile` `WAZUH_VERSION=4.14.7` → `4.14.8`** (commit `5d670d1b85`). OpenClaw's own container installs a second, separate wazuh-agent copy (HIDS/FIM for the bot workspace) independent of the wazuh-agent sidecar. The 2026-09-26 run bumped the sidecar and `docker-compose.yml`'s manager tag but missed this one — caught this run by a full-repo `grep WAZUH_VERSION`. Verified live post-rebuild: `dpkg -s wazuh-agent` inside `agentshroud-dev-openclaw` → `Version: 4.14.8-1`.
2. **`gateway/requirements.txt` `websockets>=16.1.1,<17.0` → `>=17.1,<18.0`** (commit `4785e6087a`). The cap had no CVE or compatibility comment behind it. Verified websockets 17.0's breaking changes (Python≥3.11 requirement, keyword-only bool args, ISO-8859-1 header encoding) don't hit gateway's actual usage (CI tests 3.11/3.13 only, runtime is `python:3.13-slim`, no positional-bool call sites in `ingest_api/main.py`/`proxy/slack_socket_client.py`/`proxy/canvas_proxy.py`/`cli/main.py`). `voice_gateway` already runs 17.1 uncapped with zero issues, corroborating. Verified live: `pip show websockets` inside `agentshroud-dev-gateway` → `Version: 17.1`.
3. **`scripts/lib/sunday-scan.sh` stdout leak** (commit `2d957bf113`). `_sunday_warn_expiring_acceptances()` printed its CVE-acceptance-expiry warning straight to stdout instead of through `warn()`, bypassing this library's own log-routing contract and corrupting a machine-readable capture of `sunday_run_scan_gate`'s output (test: "two erroring scans count as 0 scanned / 2 failed"). Fixed to route through `warn()` when defined, falling back to `echo` when the function is sourced/eval'd standalone (as a separate test does) so the warning is never silently dropped either way. Verified end-to-end: today's real `--phase scan` run now shows the warning correctly prefixed `[apply 04:29:10] WARN: ...` instead of a bare unprefixed line.
4. **`tests/startup_smoke/test_setup_secrets.sh` SS7 stale check window** (commit `2d957bf113`). The chmod-600 assertion on `cmd_extract()` only scanned the function's first 50 lines; the function has grown to 67 lines (more secret types added over time) pushing the still-present, still-correct `chmod 600` call out of the checked window. Bumped the window to 70. This was a test-tooling false negative, not a real permissions regression — the security property was intact throughout.

`bash scripts/smoke.sh`: 14/14 suites passing after both scan-related fixes (was 12/14 before fix #3+#4).
